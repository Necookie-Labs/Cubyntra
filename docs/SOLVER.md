## 1. Executive Summary

Cubyntra requires a deterministic, sub-second Rubik's Cube solving engine executing entirely within the client's browser without native binary dependencies or server-side computation. The solver consumes a validated 54-facelet representation of the cube and produces an optimal or near-optimal sequence of face rotations expressed in Half Turn Metric (HTM) notation.

## 2. Theoretical Foundation: Kociemba Two-Phase Algorithm

### 2.1 Group Theory & Subgroups
A standard $3 \times 3 \times 3$ Rubik's Cube has $43,252,003,274,489,856,000$ ($\approx 4.33 \times 10^{19}$) reachable states, generated by the group:
$$G = \langle U, D, R, L, F, B \rangle$$

Directly computing the shortest path to identity in $G$ via breadth-first search or $A^*$ requires prohibitive memory and time. Dr. Herbert Kociemba introduced the **Two-Phase Algorithm** (1992), which breaks the problem into two distinct coset spaces via an intermediate subgroup $H$:
$$H = \langle U, D, R^2, L^2, F^2, B^2 \rangle$$

In subgroup $H$:
1. All 12 edge orientations are correct (flip = 0).
2. All 8 corner orientations are correct (twist = 0).
3. The 4 middle-layer edges ($FR, FL, BL, BR$) remain within the middle layer ($UD$-slice).

### 2.2 Phase 1: Reduction to Subgroup $H$
- **Objective**: Transform any arbitrary cube state $S \in G$ into a state $S' \in H$.
- **Allowed Moves**: Any face turn from $\{U, U', U2, D, D', D2, R, R', R2, L, L', L2, F, F', F2, B, B', B2\}$.
- **Coordinates Evaluated**:
  - Edge Flip Coordinate: $2^{11} = 2,048$ states.
  - Corner Twist Coordinate: $3^7 = 2,187$ states.
  - Slice Permutation Coordinate: $\binom{12}{4} = 495$ combinations.
- **Search Strategy**: Iterative Deepening $A^*$ (IDA*) guided by precomputed pruning tables encoding minimum moves to reach $H$. Typically requires 7 to 12 moves.

### 2.3 Phase 2: Solving Subgroup $H$
- **Objective**: Transform $S' \in H$ to the identity (solved) state.
- **Allowed Moves**: Restricted exclusively to $\{U, U', U2, D, D', D2, R2, L2, F2, B2\}$. This invariant ensures orientations and slice membership are never broken.
- **Coordinates Evaluated**:
  - Corner Permutation Coordinate: $8! = 40,320$ states.
  - Edge Permutation Coordinate (Phase 2): $8! \times 4! = 967,680$ states.
- **Search Strategy**: Fast IDA* search restricted to $H$. Typically requires 10 to 14 moves.

### 2.4 Optimality & God's Number
- **God's Number** for the $3 \times 3 \times 3$ Rubik's Cube in Half Turn Metric is exactly **20 moves** (proven by Rokicki, Kociemba, Davidson, and Dethridge in 2010).
- Pure optimal solvers (e.g., Korf's optimal IDA*) require gigabytes of precomputed pattern databases and can take minutes to solve single positions on desktop hardware.
- The Two-Phase algorithm produces solutions averaging **21-23 moves** in under **50 milliseconds** on modern JavaScript engines, achieving the optimal balance between human speed and algorithmic efficiency.

## 3. Metric & Notation

Cubyntra strictly adheres to the standard World Cube Association (WCA) Half Turn Metric (HTM):

| Face | Clockwise ($+90^\circ$) | Counter-Clockwise ($-90^\circ$) | Half Turn ($180^\circ$) |
|:---:|:---:|:---:|:---:|
| Up ($+Y$) | `U` | `U'` | `U2` |
| Down ($-Y$) | `D` | `D'` | `D2` |
| Front ($+Z$) | `F` | `F'` | `F2` |
| Back ($-Z$) | `B` | `B'` | `B2` |
| Left ($-X$) | `L` | `L'` | `L2` |
| Right ($+X$) | `R` | `R'` | `R2` |

### Move Inversion
To reverse a move sequence during playback or undo operations:
$$(A \cdot B)^{-1} = B^{-1} \cdot A^{-1}$$
Individual move inverses:
- `U` $\leftrightarrow$ `U'`
- `U2` $\leftrightarrow$ `U2`

## 4. Implementation Architecture

### 4.1 Module Structure
```
src/solver/
├── types.ts          # Move, MoveSequence, SolveResult, SolverConfig interfaces
└── solver.ts         # solveCubeState(), parseMoveSequence(), invertMoveSequence(), verifySolution()
```

### 4.2 Facelet Mapping
The solver accepts a 54-character string with indices 0–53 ordered by facelet conventions:
```
             +------------+
             | U1  U2  U3 |
             | U4  U5  U6 |
             | U7  U8  U9 |
+------------+------------+------------+------------+
| L1  L2  L3 | F1  F2  F3 | R1  R2  R3 | B1  B2  B3 |
| L4  L5  L6 | F4  F5  F6 | R4  R5  R6 | B4  B5  B6 |
| L7  L8  L9 | F7  F8  F9 | R7  R8  R9 | B7  B8  B9 |
+------------+------------+------------+------------+
             | D1  D2  D3 |
             | D4  D5  D6 |
             | D7  D8  D9 |
             |------------+
```

### 4.3 Simulation & Solution Verification
Cubyntra implements a mathematical verification engine in `src/solver/solver.ts`:
1. `solveCubeState(faceletString)` executes the two-phase search.
2. The resulting move sequence is applied to a simulated cube model starting from the scanned state via `applyMoveSequence()`.
3. If the resulting state is not identical to `SOLVED_CUBE_STATE`, the solve is rejected as invalid before presenting to the user.

## 6. Error Handling & Edge Cases

1. **Unsolvable Parity**: If edge flip sum, corner twist sum, or permutation parity is invalid, the solver rejects execution and returns human-readable diagnostic errors:
   - `INVALID_CORNER_TWIST`
   - `INVALID_EDGE_FLIP`
   - `ODD_PERMUTATION_PARITY`
2. **Duplicate/Missing Facelets**: Handled prior to solver invocation by `src/cube/validator.ts`.
3. **Execution Timeout**: Capped at 5,000ms. If search exceeds threshold, fallback alert triggers.
